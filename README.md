# SockLock Hook Lab

Утиліта для motion-дизайнерів SockLock. Бере скрипт ролика-переможця і генерує варіанти **модифікацій**: перший кадр, першу фразу й текст на екрані для перших 1–3 секунд, а також варіанти CTA. Кожен варіант одразу перевіряється на ризикові твердження, ліміти довжини та повтори з бібліотеки вже використаних хуків. Дизайнер обирає й править варіанти в таблиці, а потім експортує CSV або бриф.

> Проблема, яку закриваємо: «Половину дня я переписую одне й те саме: беру скрипт переможця і вручну придумую нові хуки, перші фрази, варіанти тексту на екрані» (motion-дизайнер). Модифікації дають 66% EGP (ROMI 140%), а для $800k spend їх потрібно ~500 на місяць замість нинішніх ~240.

## Запуск

Потрібні Node.js 20.12+ і ключ до Claude: Anthropic API **або** Claude у Microsoft Foundry.

```bash
npm install
cp .env.example .env      # заповніть один із блоків нижче
npm start                 # http://localhost:3000
```

**Anthropic API** (`.env`):

```env
LLM_PROVIDER=anthropic
LLM_MODEL=claude-sonnet-5-5
ANTHROPIC_API_KEY=sk-ant-...
```

**Microsoft Foundry** (`.env`):

1. Foundry portal → Discover → Models → `claude-sonnet-5-5` → Deploy → Custom settings, region scope **Global**.
2. Build → Models → ваш деплоймент → Details: скопіюйте **Key** і назву ресурсу з **Target URI** (`https://<resource>.services.ai.azure.com/anthropic/`).

```env
LLM_PROVIDER=foundry
LLM_MODEL=claude-sonnet-5-5          # назва деплойменту
ANTHROPIC_FOUNDRY_API_KEY=...
ANTHROPIC_FOUNDRY_RESOURCE=<resource>
```

Код, промпт і перевірки однакові для обох провайдерів. Відрізняється лише клієнт: `AnthropicFoundry` розширює клієнт `Anthropic` і працює з тим самим Messages API.

Без ключа сторінка відкривається з поясненням, чого бракує, але кнопка генерації вимкнена.

### Вебсторінка (основний сценарій)

1. Вставте скрипт переможця (формат довільний) або оберіть приклад.
2. Оберіть кути, кількість хуків і CTA, натисніть «Згенерувати варіанти».
3. Наведіть курсор на рядок. Блок угорі покаже новий хук поруч із фразою, з якої починається незмінне тіло ролика, тож видно, чи хук у неї природно переходить.
4. Клітинки редагуються прямо в таблиці. Після правки рядок перевіряється заново.
5. Позначте потрібні варіанти. Далі «Експорт CSV» (для таблиць), «Завантажити бриф» (Markdown для продакшну) або «Додати в бібліотеку», щоб наступні генерації позначали ці хуки як повтори.

### CLI (батч і перевірка)

```bash
npm run generate -- examples/winner-01-ugc-lonely-socks.txt
npm run generate -- examples/*.txt --count 20 --angles pain,curiosity,ugc --ctas 4 --out out
npm run generate -- --help
```

Для кожного файлу створюються `out/<winner>-<час>.csv`, `.md` (бриф) і `.json` (повна відповідь з аналізом і токенами).

### Інше

```bash
npm run stats       # метрики пілоту з logs/runs.jsonl
npm test            # 26 тестів, ключ не потрібен
npm run typecheck
```

## Як це працює

```
скрипт переможця ─┐
brand/socklock.md ─┼─► prompt.ts ─► Claude (structured outputs, JSON-схема) ─► postprocess.ts ─► таблиця / CSV / бриф
бібліотека хуків ──┘                                                            ├ claims.ts      ризикові твердження, ліміти
                                                                                ├ similarity.ts  повтори з бібліотеки, з оригіналом, усередині видачі
                                                                                └ runlog.ts      події для метрик
```

- **Промпт** (`src/prompt.ts`). Модель спершу розбирає переможця: оригінальний хук, головну обіцянку, фразу, з якої починається тіло, і що лишається без змін. Потім пише рівно стільки варіантів на кожен кут, скільки попросили. Кожен хук має природно переходити в незмінне тіло ролика. Факти беруться лише з `brand/socklock.md`, а там, де потрібен доказ, модель ставить `[PLACEHOLDER]`.
- **Structured outputs.** Відповідь обмежена JSON-схемою (`src/schema.ts`, zod). SDK валідує її й повертає типізований об'єкт, тому парсити вільний текст не доводиться. Ліміти довжини навмисно не входять у схему: задовгий рядок отримує позначку, а не ламає весь запуск.
- **Перевірки** (`config/claims-rules.json`, редагують маркетологи):
  - високий ризик: твердження про здоров'я (терапія магнітами), умови поза офертою (free, discount), неправильна ціна;
  - середній: абсолютні обіцянки (never, guaranteed), суперлативи, вигадана терміновість, непідтверджений соцдоказ, числа поза офертою, перевищення лімітів (перша фраза ≤12 слів, текст на екрані ≤40 символів);
  - інфо: плейсхолдери, які треба заповнити.
- **Повтори.** Коефіцієнт Дайса по символьних триграмах: від 0,62 — дубль, від 0,45 — «схожий». Порівняння йде з бібліотекою, з оригінальним хуком і з попередніми варіантами в тій самій видачі. Метод дешевий, детермінований і зрозумілий, але ловить лише перефразування, а не ту саму ідею іншими словами (див. «Наступна ітерація»).
- **Статуси:** «готові» без зауважень, «перевірити» з позначками або схожістю, «дублі». Остаточне рішення завжди за дизайнером.

Файли, які можна міняти без коду (перечитуються на кожен запит):

| Файл | Що в ньому |
|---|---|
| `brand/socklock.md` | факти про продукт, оферту, тон і заборони; вставляється в промпт |
| `config/claims-rules.json` | ліміти, пороги схожості, регулярні вирази перевірок |
| `data/hooks_library.csv` | бібліотека хуків; обов'язкова колонка лише `first_line` |

> `examples/*.txt` і `data/hooks_library.csv` — **синтетичні** дані, створені для демо. Доступу до Airtable чи Meta SockLock немає, тож у роботі бібліотеку замінюють експортом реальних хуків.

## Вартість

Один запуск на 20 хуків і 4 CTA — це приблизно 5 тис. вхідних і 2,5 тис. вихідних токенів. На Claude Sonnet 5.5 ($2 / $10 за 1 млн токенів, у Foundry ставки ті самі) виходить ~$0,035 за запуск. На 500 модифікацій на місяць (~25 запусків) це менше $5 на місяць. Фактичні токени й вартість кожного запуску видно на сторінці та в `logs/runs.jsonl`.

## Як поміряти успіх

Інструмент сам логує кожну генерацію, експорт і збереження в бібліотеку (`logs/runs.jsonl`, звіт — `npm run stats`).

| Метрика | Зараз | Ціль | Як міряємо |
|---|---|---|---|
| Час дизайнера на текстову частину модифікації | ~1,5 год | ≤ 20 хв | час від генерації до експорту (лог) + самозвіт дизайнерів |
| Час на одну модифікацію загалом | ~3 год | ≤ 2 год | таймтрекінг тиждень до і два тижні після |
| Модифікацій на місяць тією ж командою | ~240 | ≥ 360 за 4 тижні, далі шлях до 500 | лічильник у продакшн-трекері |
| Частка прийнятих варіантів | — | ≥ 30% (6 з 20) | обрані / згенеровані (лог) |
| Частка відредагованих | — | ≤ 50% обраних | лог |
| Якість: hook rate (3-с перегляди), CTR, CPA | ручні моди | AI-моди не гірші ніж на 10% | A/B у Meta: 20 AI-мод проти 20 ручних, однаковий бюджет, 2 тижні |
| Відхилення модерацією Meta | — | 0 через твердження з позначкою «високий ризик» | статуси оголошень |

**План пілоту.** Тиждень 0 — базова лінія: дизайнери логують час на моду. Тижні 1–2 — двоє дизайнерів працюють через Hook Lab, паралельно йде A/B 20 на 20. Тиждень 4 — рішення: якщо час на моду ≤ 2 год, а CPA AI-мод у межах ±10% від ручних, розгортаємо на всіх шістьох.

## Наступна ітерація

1. **Навчання на результатах.** Додати в бібліотеку метрики (hook rate, CTR, CPA) і передавати в промпт найкращі хуки як приклади, а слабкі кути показувати рідше.
2. **Семантичні дублі.** Додати ембедінги поверх триграм, щоб ловити ту саму ідею іншими словами.
3. **Чернетки відео.** Накладати обраний текст на екрані на вихідник переможця (FFmpeg або Remotion), щоб дизайнер отримував готовий рендер, а не лише бриф.
4. **Інтеграція.** Читати й писати бібліотеку напряму в Airtable замість CSV, а результати підтягувати з експорту Meta.
5. **Локалізація DE/FR** на тому ж рушії: транскреація скрипту з лімітами довжини (проблема Head of Marketing).
6. **Eval-набір.** 30 скриптів-переможців з оцінками людей, щоб перевіряти зміни промпту на регресію; плюс prompt caching для системного промпту.

## Структура

```
src/
  schema.ts            кути, JSON-схема відповіді, типи
  prompt.ts            системний і користувацький промпти, розподіл кількості за кутами
  config.ts            .env → конфіг (zod)
  llm/client.ts        виклик Claude зі structured outputs, обробка stop_reason
  llm/index.ts         вибір провайдера: Anthropic або Foundry
  llm/pricing.ts       оцінка вартості за токенами
  core/generate.ts     оркестрація запуску
  core/postprocess.ts  статуси, дублі, перевірки
  core/claims.ts       правила, числа, ціни, ліміти
  core/similarity.ts   коефіцієнт Дайса на триграмах
  core/library.ts      читання й дописування CSV-бібліотеки
  core/runlog.ts       події для метрик
  export/exporters.ts  CSV (з BOM для Excel) і Markdown-бриф
  server.ts            Express API + статична сторінка
  cli.ts               батч-режим
  stats.ts             звіт по метриках
public/                сторінка дизайнера (HTML, CSS, JS без збірки)
test/                  юніт-тести і тести через локальну заглушку Messages API
```

Тести `test/integration.test.ts` піднімають локальну заглушку Messages API і проганяють через неї справжні клієнти Anthropic і Foundry SDK. Так без ключа перевіряються URL, авторизація, JSON-схема в запиті й розбір відповіді.
